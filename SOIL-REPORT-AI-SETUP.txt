KHETMITRA — GEMINI SOIL REPORT ANALYSIS

1. Create a Gemini API key in Google AI Studio: https://aistudio.google.com/apikey
2. Copy .env.example to .env.local.
3. Set GEMINI_API_KEY to your key. Keep this key server-side; do not use a NEXT_PUBLIC_ prefix.
4. Restart the Next.js server.
5. Open onboarding > Soil test report and upload a PDF, JPG, PNG, or WEBP Soil Health Card (maximum 15 MB).

The /api/soil-report endpoint sends the uploaded document to Gemini 3.8 Flash, with Gemini 3.5 Flash-Lite as a fallback and asks it to extract only printed values. It classifies the document as valid, incomplete, or invalid. It retries temporary Gemini 503/429/5xx capacity errors and falls back to Gemini 3.5 Flash-Lite if the primary model is unavailable. For valid/incomplete reports, detected values are copied into the existing pH, Organic C, N, P, and K inputs. Missing values are left as currently entered so they can be completed manually. Invalid documents do not overwrite the form.

GPS autofill already exists on the Land step and is unchanged. It uses browser location permission and the existing reverse-geocoding API.

Privacy: uploaded report bytes are sent to Google's Gemini API for analysis and are not saved by this endpoint. Configure your Google AI account and deployment according to your privacy requirements.

Model note: Newly created Google AI Studio projects should use Gemini 3.8 Flash or Gemini 3.5 Flash-Lite; access to Gemini 2.5 generation is restricted for projects without prior usage.
